## Users

매일 같은 버스·지하철로 출퇴근하는 일반 직장인입니다. 이들은 길을 이미 압니다. 알고 싶은 것은 자기가 늘 타는 차가 지금 어디 있는지, 그래서 지금 나가야 하는지입니다.

쓰는 상황은 집을 나서기 직전, 정류장으로 걷는 중, 정류장과 승강장에서 기다리는 중, 차 안입니다. 대부분 잠금화면을 흘끗 보는 정도이고, 한 손에 휴대폰을 들고 걸으면서 봅니다.

## Product Purpose

Betro는 서울 지하철과 버스가 지금 어디 있는지 보여 주는 앱입니다. 길찾기 앱이 아니라 "내가 매일 타는 차를 대신 지켜봐 주는 앱"입니다.

1차 출시의 중심은 출퇴근 Live Activity(iOS, 다이내믹 아일랜드 포함)와 Live Update(Android)입니다. 사용자가 정해 둔 시각이 되면 잠금화면에 내가 탈 차가 어디쯤이고 내 정류장에 몇 시 몇 분에 오는지를 자동으로 띄우고 계속 갱신합니다. 평소 경로가 늦어지면 사용자가 미리 등록해 둔 대안 경로 가운데 더 빠른 것을 제안합니다.

앱 안에는 실시간 지도, 검색, 열차·버스·역 상세, 즐겨찾기, 내 장소가 함께 들어갑니다.

성공의 뜻은 출시 기준으로 정해져 있습니다. 평일 2주 동안 실제 출퇴근에 써서 자동 시작이 정해 둔 시각 ±1분 안에 20회 중 20회 뜨고, 도착 5분 전 예측이 ±1분 이내 80% 이상, ±2분 이내 95% 이상이며, 2분 넘게 갱신이 멈춘 경우와 도착 뒤에도 잠금화면에 남는 경우가 0회여야 합니다. 상세는 `docs/superpowers/specs/2026-11-05-mvp-design.md` 7장에 있습니다.

## Positioning

카카오맵과 네이버지도는 목적지를 검색하고 "안내시작"을 눌러야 시작하는 길찾기 중심 앱이라, 매일 같은 길을 가는 사람도 매번 같은 절차를 거칩니다. Betro는 이 반복을 없앱니다.

차별점이 아닌 것: 실시간 차량 지도, 잠금화면 Live Activity, 출퇴근 장소 등록, 버스와 지하철 모두 지원. 네이버(2024-04)와 카카오(2026-10)가 이미 냈으므로 갖춰야 할 기본 조건입니다.

아직 아무도 하지 않는 것: 정해 둔 시각에 자동으로 시작하는 것, 등록한 대안 경로를 비교해 제안하는 것.

따라 하기 어려운 차별점 세 가지:

1. **내 출근길에서만큼은 가장 정확하게.** 출퇴근 세션의 노선을 집중 관측하고, 예측과 실제를 기록하며, 확신이 없으면 "시간표 추정"으로 표시합니다.
2. **정보만 보여 주지 말고 할 일을 알려 주기.** 사용자의 도보 시간과 등록된 대안을 알기 때문에 "08:10에 나가면 딱 맞아요", "360번 타면 6분 빨라요" 같은 말을 할 수 있습니다.
3. **가볍고 변하지 않기.** 로그인 요구, 실행 시 팝업, 전면 광고가 없습니다. 출퇴근 흐름은 개편으로 흔들지 않습니다.

## Operating Context

- **잠금화면이 주 무대입니다.** 핵심 가치는 앱을 열지 않아도 된다는 것입니다. 앱 화면은 등록할 때와 자세히 볼 때 씁니다.
- **출퇴근 흐름**: 내 장소(집, 회사, 학교, 기타) 등록 → 자주 타는 경로와 대안 2~3개를 직접 선택 → 요일과 집에서 나가는 시각 예약 → 나가는 시각 10분 전에 자동 시작 → 도보, 대기, 탑승, 도착 4단계로 갱신 → 도착하면 종료.
- **잠금화면 버튼**: 탑승 전 단계에 "탔어요", "다음 차 탈게요"를 둡니다. 누르지 않아도 시각으로 추정해 동작합니다.
- **하단 탭**: 지도 / 즐겨찾기 / 출퇴근 / 설정.
- **데이터 상태 네 가지**: 실시간, 시간표 추정, 지연, 운행 종료. 화면마다 정보의 출처와 정확도를 함께 표시합니다.
- **데이터의 성질**: 서울 지하철 실시간 API는 좌표 없이 역 단위 상태(진입, 도착, 출발)만 줍니다. 열차 위치는 선로 형상과 시간표로 역 사이를 보간하고 실시간 상태로 보정한 값입니다. 버스는 좌표를 주지만 갱신 간격이 길어 노선 형상을 따라 보간합니다.
- **API 한도**: 실시간 지하철 API는 인증키당 하루 1,000회입니다(활용사례 승인 전). 한도를 넘기면 그 소스는 시간표 추정 모드로 바뀌고 화면에 표시됩니다.
- **지도**: 네이버 지도를 씁니다. 지도 위 차량은 정지 이미지가 아니라 갱신 사이에도 계속 움직입니다.

## Capabilities and Constraints

**1차 출시 범위**

- 화면: 온보딩, 권한(위치·알림), 지도 홈, 시간표 추정 모드, 검색, 열차·버스·역 상세, 즐겨찾기, 내 장소, 장소 설정, 출퇴근 안내, 설정(게스트), 데이터 출처, Live Activity, Dynamic Island, Live Update.
- 로그인 없이 모든 기능이 동작합니다.
- iOS와 Android를 함께 출시합니다. iOS 최소 버전은 17.2입니다.
- 서울 지하철, 서울 시내버스, 서울 마을버스는 지도·검색·상세·출퇴근에 모두 들어갑니다. 경기·인천 버스는 출퇴근 경로 등록과 추적에만 들어갑니다.
- 앱은 사용자가 등록한 경로끼리만 비교합니다. 경로를 찾아 주지 않습니다.
- 한국어만 지원합니다. 문구는 `lib/i18n/messages-ko.ts` 한 곳에서 관리합니다.

**범위 밖 (출시 이후)**

- 로그인과 기기 간 동기화. 넣게 되면 SSO만 씁니다(iOS: Apple·카카오·네이버·Google, Android: 카카오·네이버·Google).
- 역·방향 기준 도착 알림 설정과 알림함.
- 길찾기, 등록하지 않은 노선 제안.
- 경기·인천 버스의 지도 표시, 검색, 상세.
- 광고, 인앱 결제, 유료 구독, 다국어, 해외 도시.

**지켜야 할 제약**

- 서버에 사용자의 집·회사 주소와 좌표를 저장하지 않습니다. 서버에는 경로 구간(노선, 승차·하차 정류장, 방향)과 요일·시각만 둡니다.
- 공공 API 키를 앱에 넣지 않습니다.
- 갱신이 멈췄는데 화면이 "실시간"처럼 보이면 안 됩니다. 데이터가 끊기면 "시간표 추정"으로 바꿔 표시합니다.
- 출퇴근 흐름(잠금화면에서 연 화면, 출퇴근 안내)에 팝업, 광고, 로그인 요구를 넣지 않습니다. 잠금화면에는 광고를 넣지 않습니다.
- 1차 출시에 들어간 기능은 앞으로도 무료입니다. 장소 수와 예약 요일을 제한하지 않습니다.
- 데이터 출처(OpenStreetMap ODbL, 공공누리)를 앱 안에 표기해야 합니다.

**아직 정해지지 않은 것**

- 경기·인천 버스를 전체로 다룰지, 서울을 오가는 노선만 다룰지. 데이터 출처 실험 결과를 보고 정합니다.
- 환승 경로에서 진행 표시의 노드를 늘리는 방식.
- 유료 구독과 광고를 시작하는 시점과 유료 기능의 범위.

## Brand Commitments

- 이름은 Betro입니다.
- 로고는 루프 워드마크입니다. 구현은 `components/brand/logo.tsx`, 앱 아이콘과 스플래시는 `assets/images/`에 있습니다.
- 디자인 원본은 Figma [Betro App UI](https://www.figma.com/design/MiS0r5xYKVht3Pc7YXMXpP/Betro-App-UI)입니다. 앱 UI는 이 파일의 변수와 컴포넌트를 따릅니다(`AGENTS.md`).
- 문구는 해요체로 씁니다. 예: "지금 달리는 차량이 어디쯤 있는지 한눈에 보여드려요."
- 상태 문장은 정보 나열보다 사용자가 할 일을 알려 주는 쪽으로 씁니다.
- 사용자 행동을 단정하지 않습니다. "놓쳤어요", "늦었어요" 대신 차량에 대한 사실("341번이 지나갔어요")과 조건문("08:10에 나가면")으로 씁니다. 확신이 낮을 때는 "시간표 추정 · 약 3분"처럼 씁니다.

## Product Principles

1. **위치가 먼저, 시각은 그다음.** "2정거장 전" 같은 위치는 시각이 틀려도 사용자가 스스로 판단할 수 있게 해 줍니다. 도착 예측의 확신이 낮을 때도 위치는 계속 보여 줍니다.
2. **모르는 것은 모른다고 표시한다.** 실시간과 추정을 구분하고, 멈춘 데이터를 살아 있는 것처럼 보이게 두지 않습니다.
3. **할 일을 알려 주되 단정하지 않는다.** 정보 나열보다 다음 행동을 말하고, 사용자가 무엇을 했는지는 추측으로 말하지 않습니다.
4. **열지 않아도 되는 앱.** 가장 중요한 순간은 잠금화면에서 끝납니다. 앱을 열게 만드는 장치를 두지 않습니다.
5. **출퇴근 흐름은 흔들지 않는다.** 매일 쓰는 흐름에 팝업, 광고, 로그인, 잦은 개편을 끼워 넣지 않습니다.

## Accessibility & Inclusion

- WCAG 2.2 AA를 기준으로 합니다. 본문과 보조 텍스트의 대비는 4.5:1 이상입니다.
- iOS Dynamic Type과 Android 글꼴 배율에 대응합니다.
- 노선과 데이터 상태를 색만으로 구분하지 않습니다. 노선 번호와 이름, 상태 글자를 함께 씁니다.
- 스크린리더(VoiceOver, TalkBack) 라벨을 제공합니다.
